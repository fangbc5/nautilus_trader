# 路线图

> 本文档为 [English 原文](../ROADMAP.md) 的中文翻译版本。如有歧义请以英文原版为准。

本文档概述 **NautilusTrader** 的关键优先事项与近期目标，规划其作为生产级、Rust 原生交易引擎的发展路径。

鉴于项目具有动态性，优先事项可能会随着快速演进的开发周期而调整。
如需获取实时更新和详细的任务跟踪，请参阅 [NautilusTrader 看板](https://github.com/orgs/nautechsystems/projects/3)。

**注意**：为确保稳定性与进展，缺陷修复和路线图优先事项优先于功能请求。然而，针对改进和新特性的 pull request（PR）始终欢迎。
更多详情，请参阅 [CONTRIBUTING.md](/CONTRIBUTING.md)。

## 愿景

将 NautilusTrader 打造为量化算法交易领域默认的开源交易引擎，结合生产级架构、可靠性和文档，服务交易者与开发者。

## 优先事项

1. **将核心移植到 Rust**

   **目标**：利用 Rust 的性能与安全特性，提升可靠性、性能和可扩展性。
   - 用 Rust 重写性能关键组件（替换现有 Cython 模块）。
   - 通过 PyO3 确保 Rust 与 Python 层之间的互操作性。
   - 在整个迁移过程中对性能改进进行基准测试。

2. **改进文档与教程**

    **目标**：降低新用户的学习曲线，并通过清晰、全面的指南赋能开发者：
   - 通过补齐缺失章节，填补用户和开发者文档的空白。
   - 增加更多教程和示例。

3. **改进代码人体工学**

    **目标**：为用户和贡献者简化开发体验：
   - 增强类型注解，并支持 Python import 解析。
   - 标准化命名约定，优化 API 以更直观。
   - 简化配置和搭建流程，减少摩擦。
   - 重构模块和命名空间，提升可读性与可维护性。

## 其他增强

在推进上述优先事项的同时，我们也计划着力于以下增强：

- 扩展适配器集成，支持更多交易场所和数据提供商。
- 通过增加更多功能来增强回测引擎。
- 通过增加更多功能来增强订单簿执行动态，包括用户订单交互、持久化订单簿变化以及扩展的微观结构模拟。
- 针对本地单节点工作流的回测可视化，包括图表和绩效报告（tear sheets），但不包括完整的 UI 仪表盘。

## 开源范围

NautilusTrader 开源项目专为赋能个人和小型团队的量化交易者而构建，使其能够在单一节点上高效、可靠地进行策略研究和实盘交易。通过明确界定哪些 *属于* 范围、哪些 *不属于* 范围，我们设定了清晰的预期，聚焦社区努力，并支持可持续的开源生态系统。

### 范围内

- 高性能的单节点回测，准确模拟实盘交易条件。
- 在单节点基础设施上的实盘交易，实现从研究到生产的流畅工作流。
- 针对额外交易场所和数据提供商的 [社区贡献集成](#community-contributed-integrations)。

### 范围外

- UI 仪表盘或前端：重心仍严格集中在核心交易引擎上。前端贡献会分散对引擎的关注，并带来不可持续的维护负担。
- 分布式或大规模并行回测编排：通过外部编排的工作流在技术上是兼容的，但内置的分布式 runner 超出了项目当前的范围。
- 集成的超参数优化或内置的 AI/ML 工具：用户应集成自己量身定制的优化框架。
- 额外的外部集成（例如云服务、数据库和监控工具）：除非明确列出，否则均不在范围内。

## 社区贡献的集成

新增集成是该项目的一项重大工作。它们不仅仅是初始代码：文档、教程、维护和持续的用户支持都是使其可行和可持续所必需的。
由于贡献者没有义务完成或维护一项集成，因此我们必须在将其纳入主项目之前，仔细权衡其长期影响和承诺。

目前，项目支持新增官方集成的带宽有限。

为了设定更清晰的预期：

**第 1 步 — 开启 RFC**

在为新增集成开启 PR 之前，贡献者应首先开启一个 Request for Comments（RFC）issue。
这允许在编写任何代码之前讨论其适用性、与路线图的契合度以及维护方面的考量。

**第 2 步 — 评估**

维护者会根据稳定性、需求、技术契合度和可用带宽等因素评审 RFC。
集成还必须与 NautilusTrader 专业、注重性能、高可靠性的理念保持一致。
只有在这一阶段达成共识后，才应考虑 PR。

**第 3 步 — 提交 PR（如获批准）**

如果 RFC 获得批准，贡献者可以继续提交 PR。
集成必须严格遵循现有的基于 Rust 的适配器实现模式，以确保一致性和可维护性。
即便如此，是否纳入官方发行版仍取决于长期可持续性和可用资源。

关于适配器分类、社区列名和支持边界，请参阅 [ADAPTERS.md](ADAPTERS.md)。关于独立项目的命名规则与免责声明要求，请参阅 [TRADEMARK.md](TRADEMARK.md)。

## 长期承诺

NautilusTrader 是一个开源核心（open-core）项目。所有核心交易引擎特性都首先在公开仓库中落地，我们致力于持续扩展功能集并改进文档，让社区能够依赖一个现代化、生产级、经过实战检验的交易引擎。

用户的反馈和贡献直接影响着路线图；随着真实世界需求的演进，我们将稳步提升开源代码库可实现能力的上限。

## NautilusTrader v2.0 及之后

- **达到稳定状态**：尽管 NautilusTrader 已在生产环境中成功使用，但 v2.0 代表着朝向建立稳定 API 的重要里程碑。
- **关注重点**：v2.0 计划将优先考虑 API 一致性、长期可维护性，并满足实盘交易环境的严苛标准。
- **正式弃用**：v2.0 将引入正式的弃用机制，使采用变更和新特性更加容易，同时为开发者保持清晰。
- **Python API 承诺**：尽管将核心迁移到 Rust，NautilusTrader 仍将继续提供面向用户的 Python API。

## 擘画未来

本路线图建立在 NautilusTrader 坚实的基础之上，在持续打磨的同时，为算法交易者和开发者拓展其可能性与能力。
