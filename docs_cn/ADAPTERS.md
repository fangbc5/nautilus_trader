# 适配器与集成

> 本文档为 [English 原文](../ADAPTERS.md) 的中文翻译版本。如有歧义请以英文原版为准。

本文档说明 NautilusTrader 如何对适配器进行分类、不同层级之间的转换路径，以及社区适配器如何被列入名单。

关于命名规则、免责声明要求以及商标指引，请参阅 [TRADEMARK.md](./TRADEMARK.md)。

## 适配器层级

### 官方（Official）

在 [nautilus_trader](https://github.com/nautechsystems/nautilus_trader) 仓库或 [nautechsystems](https://github.com/nautechsystems) GitHub 组织中维护，并由项目维护者指定为官方适配器。由维护者提供文档和支持。

**要求：** 战略与技术上的契合、可维护性、需求、法律适用性，以及与 NautilusTrader 领域模型和标准适配器模式的一致性。

### 社区（Community）

由第三方作者自行维护的适配器，因在评审时满足列名标准而被列入本文档。列名并不代表官方背书、支持或官方身份。

### 外部（External）

存在于项目之外，且未作为社区适配器列入本文档的第三方适配器。外部适配器的存在与否由其维护者自行决定。

## 采纳路径

适配器可以在不同层级之间转换。以下路径相互独立，社区列名并非官方采纳的前置条件。

**外部转社区。** 维护者通过开启一个 GitHub issue 或讨论申请社区列名。维护者将根据列名标准进行评审。

**晋升为官方。** 适配器维护者或社区成员按照 [ROADMAP](./ROADMAP.md#community-contributed-integrations) 中描述的流程开启一个 RFC。维护者会依据既有标准进行评估：稳定性、需求、技术契合度、维护带宽，以及与 Rust 适配器模式的一致性。如获批准，适配器将被纳入核心仓库或 nautechsystems 组织，必要时重新授权许可，并按项目标准进行维护。

### 降级

如果官方适配器落后于核心 API，或相对于需求、架构契合度和项目标准而言不再值得持续维护，则可能被归档或移交给社区维护者。只有在有维护者愿意接手时，适配器才会转为社区层级；否则将变为外部层级或被归档。

### 被拒绝的 RFC

被拒绝的 RFC 并不会将适配器从生态系统中移除。该适配器仍可保持社区或外部状态，并遵循 [TRADEMARK.md](./TRADEMARK.md) 中所规定的常规命名与免责声明要求。

### 现有适配器

目前位于核心仓库中的所有适配器，按定义均为官方适配器。本框架自此之后生效适用。

## 支持

NautilusTrader 维护者仅为官方适配器提供支持。社区或外部适配器的问题应直接反馈给其各自的维护者。

如果你认为问题源自 NautilusTrader 核心，而非第三方适配器，请向 [核心仓库](https://github.com/nautechsystems/nautilus_trader/issues) 提交一个最小可复现示例。

## 社区列名

此处列出的社区适配器在评审时满足列名标准。

### 列名标准

- 符合 [TRADEMARK.md](./TRADEMARK.md)（命名与免责声明）。
- 采用与 LGPL v3.0 *兼容* 的开源许可证。
- 维护者身份可识别且可联系。
- 仓库在过去六个月内有活动。
- 仓库包含安装或使用文档。

### 如何列名

开启一个 GitHub issue 或讨论，附上仓库链接和简要描述。维护者将根据上述列名标准进行评审，并决定是否加入列表。

如果社区列名不再满足列名标准，或对其与 NautilusTrader 的关系进行了不实陈述，维护者可更新或移除该列名。

### 社区适配器

社区适配器由外部维护，NautilusTrader 维护者不提供支持。
