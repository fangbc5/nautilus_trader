# 设计原则

> 本文档为 [English 原文](../../docs/developer_guide/design_principles.md) 的中文翻译版本。如有歧义请以英文原版为准。

## 消息不可变性

一旦消息（请求、响应、事件或命令）被创建，其字段就不得被修改。
参见 [消息总线：消息完整性](../concepts/message_bus.md#message-integrity) 了解由此衍生的所有权规则。

该不变量保护了系统所依赖的若干属性：

- **确定性**：每个消费者都看到相同的输入。行为更容易推理、重放和测试。
- **时间完整性**：消息保留了系统发出它时所呈现的事实。事件和命令始终是事实记录，而不是承载漂移状态的容器。
- **更安全的并发**：读者无需协调即可避免后续重写破坏消息载荷。这就消除了围绕共享状态产生竞态的常见根源。
- **更易调试**：日志、追踪、重放工具以及死信检查依然有用，因为消息仍反映原始载荷。
- **可靠的重放与仿真**：重放一个序列可得到与原始运行相同的逻辑输入。这支持回测、事故复盘和回归测试。
- **清晰的所有权边界**：组件将接收到的消息视为输入。如果组件需要不同的表示形式，它应显式派生新的局部状态或新的消息。
- **更好的可审计性**：系统可以回答它知道什么、何时知道、以及基于该信息做了什么。
- **更鲁棒的分布式**：序列化的消息已经作为副本跨进程和服务边界传递。同样的所有权规则使内存中的模型与之保持一致。
